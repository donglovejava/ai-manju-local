# 原理、完整流程与生态调研

> 本文基于本机（RTX 4060 Laptop 8GB / 16GB RAM）实际搭建并跑通的结果写成，不是二手资料。

---

## 一、为什么不用即梦也能做视频

### 1.1 两种路线的本质区别

即梦、可灵、海螺这类产品，本质是**端到端黑盒**：

```
你输入一句话 → 云端大模型 → 直接吐出视频
```

它们背后是闭源的视频生成大模型（DiT 架构为主）+ 大规模集群 + 产品层封装。你付的是"结果"，不掌握过程。

本地做的是**拆解流水线**：

```
小说 → 分镜脚本 → 静图 → 运镜 → 配音 → 字幕 → 合成
        每一步都是一个可替换的模块
```

关键认知：**"漫剧"不是"AI 生成视频"，而是"AI 生成素材 + 传统剪辑工艺"**。

一部 3 分钟的漫剧，约 60 个镜头：

| 成分 | 是否用生成模型 |
|---|---|
| 60 张静图 | ✅ 图像扩散模型（每张 10–15 秒） |
| 镜头的"动" | ❌ 不是 AI，是 FFmpeg 的 `zoompan` 几何变换（推/拉/摇/移） |
| 配音 | ✅ 语音合成模型 |
| 字幕 | ❌ 文本渲染 |
| 转场/混音/拼接 | ❌ FFmpeg |

也就是说，**真正需要"生成模型"的只有两件事：出图和配音**。视频的"动"是后期做的，成本几乎为零。这就是本地 8GB 显卡能做出漫剧的根本原因——你没有在跑一个视频大模型，你在跑一个"静止画面工厂"。

### 1.2 本地实际跑的模型与分工

| 环节 | 模型 | 显存 | 单次耗时 | 作用 |
|---|---|---|---|---|
| 分镜拆解 | DeepSeek-V3（云端）或本地 Qwen3-8B | 0 / 5GB | 20–60 秒/章 | 把中文小说变成结构化镜头表（景别、动作、情绪、台词） |
| 出图 | **Illustrious-XL v2.0**（SDXL 架构，6.9GB） | 6–7GB | 10–15 秒/张 | 韩漫/条漫风格静图，768×1344 |
| 放大 | RealESRGAN / 4x-UltraSharp | 1–2GB | 8 秒/张 | 768→1536，供 1080p 裁切 |
| 配音 | IndexTTS-2 / CosyVoice2 / edge-tts | 3–4GB / 0 | 1–2 秒/句 | 中文情感配音，可零样本克隆音色 |
| 口型 | LatentSync 1.6（可选） | 4–5GB | 30 秒/镜头 | 对话特写时对齐嘴型 |
| 运镜 | —— | 0 | CPU 实时 | `zoompan` 缓动，六种基础镜头 |
| 合成 | FFmpeg | 0 | CPU 实时 | 拼接、混音、字幕烧录、编码 |

**为什么是 SDXL 而不是 Flux？**
Flux 画质更好、提示词理解更强，但 dev 版 12B 参数，8GB 必须用 Q4 GGUF 量化，速度慢 3–5 倍且显存频繁换入换出。SDXL 架构的动漫微调模型（Illustrious / NoobAI / Pony）在 8GB 上是"刚刚好"的甜点区：原生 1024 分辨率、10 秒出图、社区 LoRA 生态最大。

### 1.3 一年前后到底变了什么

你观察到的现象——"一年前只是图文视频，现在动辄几十到几百集"——不是模型变强了 10 倍，而是**单位成本降了 10 倍，并且流程被自动化了**。

拆开看四个环节：

| 环节 | 2024 年做法 | 2026 年做法 | 成本变化 |
|---|---|---|---|
| 画面 | 找素材库配图 / 请画师（200–500 元/张） | 本地显卡 10 秒/张（电费≈0.02 元） | **约 1/10000** |
| 分镜 | 人写 Excel，一天 1 集 | LLM 结构化输出，20 秒/章 | **约 1/1000** |
| 配音 | 找 CV 录制（300–800 元/集） | TTS，1 秒/句 | **约 1/1000** |
| 剪辑 | 手动拖时间轴，2–3 小时/集 | 脚本批量合成，20 分钟/集 | **约 1/10** |

三个技术拐点促成了这件事：

1. **2024.8 Flux 发布** —— 用 T5 文本编码器，让"文本理解"第一次真正可靠。此前 SD1.5/SDXL 需要大量咒语式 prompt 调试，普通人做不出稳定画风。
2. **动漫垂直底模成熟** —— Illustrious（2024 末）、NoobAI 等基于 SDXL 微调的模型，把"出好看的二次元图"变成开箱即用，且 danbooru 标签体系让控制变得精确（`1girl, solo` 比 "only one person" 有效得多，实测验证）。
3. **ComfyUI 的 API 化** —— 节点图可以序列化成 JSON，通过 HTTP 批量提交。这让"脚本调用出图"成为工程实践，而不是每次手动点按钮。

但要说清楚：**质量天花板没有本质提升**。画质够用了，但"同一个角色跨 60 个镜头保持同一张脸"仍然是行业难题。头部漫剧团队都在做同一件事——**训练角色 LoRA**，靠人工筛图 + 重抽来保证一致性。这是当前的技术边界，也是为什么"几百集"的公司都有专门的修图岗。

## 二、整本小说 → 连载漫剧的完整流程

### 2.1 十二步流水线

```
┌─ 0. 立项拆集 ─────────────────────────────┐
│  按每集 1000–1500 字切分（≈3 分钟成片）      │
│  20 万字的书 → 约 220 集                    │
└────────────────────────────────────────────┘
              ↓
┌─ 1. 系列圣经（Series Bible）───────────────┐
│  角色卡：外貌/服装/年龄锁/性格（YAML）        │
│  风格锁：画风前缀 + 负面词 + 色板            │
│  世界观：地点、时代、季节                    │
│  ★ 这是连载一致性的根基，一次定好，全书复用    │
└────────────────────────────────────────────┘
              ↓
┌─ 2. 角色设定图 + LoRA（推荐）──────────────┐
│  每个主要角色出 4 视图（正/侧/背/四分之三）   │
│  筛 20–30 张干净图 → 训 LoRA（1.5–2 小时）   │
│  ★ 不训 LoRA 也能做，但一致率从 ~60% 掉到 ~30%│
└────────────────────────────────────────────┘
              ↓
┌─ 3. 文本切分 ──────────────────────────────┐
│  章节 → 场景 → 镜头（保留原文分场标记）       │
│  实测：120 章 / 15.9 万字 / 1.35 万镜         │
└────────────────────────────────────────────┘
              ↓
┌─ 4. LLM 分镜 ──────────────────────────────┐
│  每块 ≤600 字原文（防 8K token 截断）        │
│  输出 JSON：景别/角色/动作/表情/道具/情绪/时长 │
│  ★ 视觉字段强制英文，台词保留中文原文         │
│  ★ 校验：任何改写原文的台词一律剔除           │
└────────────────────────────────────────────┘
              ↓
┌─ 5. 提示词构建 ────────────────────────────┐
│  风格锁 + 景别 + 角色卡 + 动作 + 场景 + 光线  │
│  清洗：删人名（未登录 token）、统一服装        │
│  长度控制：CLIP 只有 77 token，核心词往前提    │
└────────────────────────────────────────────┘
              ↓
┌─ 6. 批量出图 ──────────────────────────────┐
│  每镜出 3–4 张（固定 seed 基座 + 偏移）       │
│  768×1344，28 步，DPM++ 2M Karras            │
│  实测 10–15 秒/张，8GB 稳定                  │
└────────────────────────────────────────────┘
              ↓
┌─ 7. 筛选与重抽 ────────────────────────────┐
│  人工抽检 or CLIP 相似度比对                  │
│  崩坏类型：多人物拼贴 / 性别错 / 手部畸变      │
│  实测崩坏率 20–30%，需预留重抽预算            │
└────────────────────────────────────────────┘
              ↓
┌─ 8. 配音 ──────────────────────────────────┐
│  每句台词单独出 wav（便于对齐时间轴）         │
│  音色按角色分配；情感参考音频驱动             │
└────────────────────────────────────────────┘
              ↓
┌─ 9. 运镜 ──────────────────────────────────┐
│  按景别选运动：特写用推拉，全景用摇移          │
│  zoompan + 2x 工作分辨率，避免边缘抖动        │
└────────────────────────────────────────────┘
              ↓
┌─ 10. 字幕 ─────────────────────────────────┐
│  字幕是漫剧节奏的一部分，不是附属品            │
│  ASS：1080 宽 48–54px，底部安全区 180–200px   │
└────────────────────────────────────────────┘
              ↓
┌─ 11. 合成 ─────────────────────────────────┐
│  视频拼接 + 音轨混合 + BGM（-18dB 垫底）      │
│  输出 1080×1920 / 30fps / H.264 + AAC        │
└────────────────────────────────────────────┘
```

### 2.2 连载化的关键：系列圣经

单集做得好不难，**跨集一致才是连载的门槛**。必须冻结四样东西：

1. **角色卡** —— 每个角色的描述逐字复用，不允许模型自由发挥外貌词
2. **风格锁** —— 画风前缀、负面词、色板全局统一
3. **Seed 基座** —— `stable_seed(shot_id)` 让每集每镜可复现，坏图能精准重抽
4. **角色 LoRA** —— 前 3–5 集收集好图后训练，之后所有集复用

### 2.3 产能与成本（本机实测）

| 指标 | 实测值 |
|---|---|
| 单张出图 | 10–15 秒 |
| 单集 60 镜（含重抽 20%） | 约 60 × 1.2 × 12s ≈ 14 分钟出图 + 10 分钟后期 ≈ **25 分钟** |
| 单集人工介入（筛图/改分镜/调字幕） | 30–60 分钟 |
| 全本 220 集纯算力 | 约 90 小时（连续跑 4 天） |
| 全本人力（按每集 45 分钟） | 约 165 小时（1 人 1 个月） |

结论：**算力不再是瓶颈，人力才是**。真正的规模化靠两件事：自动化筛图 + 减少重抽率（也就是训 LoRA）。

### 3.3 共同模式与空位

**共同模式（四条）**：

1. **角色四视图**：AIComicBuilder 的做法值得抄——每个角色先出正/侧/背/四分之三视图，作为后续所有帧的参考。这比单张参考图强得多。
2. **首尾帧 + 插值**：生成镜头的起始帧和结束帧，让视频模型补中间。比纯文生视频可控。
3. **多供应商抽象层**：所有项目都把"模型调用"抽象成 adapter，方便换供应商。
4. **FFmpeg 收尾**：无一例外，最后一步都是 FFmpeg 合成。

**空位（我们的机会）**：

| 维度 | 现状 | 机会 |
|---|---|---|
| 部署形态 | 几乎全是云 API 编排，用户要自备 5–8 个 API key | **全本地单卡可跑**，零 API 依赖（除了可选的 LLM） |
| 中文小说适配 | 多数是英文 prompt 思路，不理解中文分场标记、第一人称叙事 | **中文小说专用**：括号分场、视角切换、台词提取 |
| 硬件门槛 | 默认用户有 24GB+ 显卡或直接上云 | **面向 8GB 消费级显卡**（4060 笔记本）做针对性优化（量化、分块、串行调度） |
| 可复现性 | 随机 seed，同提示词出图不同 | **stable_seed + 逐镜重抽**，工程可控 |
| 成本透明 | 按 API 计费，不可预算 | 只有电费，产能可精确估算 |

## 四、开源方案

### 4.1 定位

> **第一个面向 8GB 消费级显卡的中文小说 → 漫剧全本地流水线。**

一句话卖点：**一台游戏本，一块 4060，从小说到成片，零 API 费用。**

差异化不是"功能更多"（比不过 AIComicBuilder 的完成度），而是三个"别人不做"：

1. **真本地** —— 除可选的 LLM 分镜外，全链路离线
2. **中文小说原生化** —— 理解括号分场、`【她】` 视角切换、`我说：` 台词标记
3. **可复现的工程** —— 固定 seed、崩坏率统计、逐镜重抽
